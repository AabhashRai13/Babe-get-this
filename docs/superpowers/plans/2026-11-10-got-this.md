# Got This Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Record every tick as a purchase for everyone on the list, and use that history for a "Bought 3 days ago" hint and "Running low?" suggestions with one weekly notification.

**Architecture:** A new `feature/gotthis` package. Pure-Kotlin domain rules (`ItemKey`, `ItemGroups`, `ItemJudge`, `ShopDay`, `Days`, `GotThisIds`) judge purchases read from Room. A tick writes the item, a local purchase and a `tick_outbox` event in one Room transaction; `GotThisSync` uploads events to the `record_ticks` RPC, and a Postgres trigger on `ticks` creates one purchase per person on the list. Purchases come back through the account catch-up, guarded by a reset watermark.

**Tech Stack:** Kotlin, Room, Hilt (ksp), supabase-kt 3.0.3 (PostgREST + RPC), WorkManager with `hilt-work`, Jetpack Compose + Material 3, Robolectric, MockK, Kover; Postgres (Supabase) with pgTAP and `pg_cron`.

**Spec:** `docs/superpowers/specs/2026-11-09-got-this-design.md` (read it first; decision and invariant numbers below, D1–D21 and I1–I7, refer to it).

## Global Constraints

- **Ids** are MD5 of UTF-8 text formatted `8-4-4-4-12` with no version bits. `tick_id = md5("<item id>:<epoch millis>")`, `purchase_id = md5("<user id>:<tick_id>")`, guest `md5("guest:<tick_id>")`.
- **Pinned vector** (Kotlin and SQL must both produce it): item `11111111-1111-1111-1111-111111111111`, tick time `2026-11-01T10:00:00Z` = `1793527200000` → tick `ce0087de-31d1-fb82-a1e7-70abb1f8ce87`; user `22222222-2222-2222-2222-222222222222` → purchase `c680a8ae-0383-3f3c-356c-4a16906dd012`; guest → `5ff805ee-b6fa-6688-3ae9-d990ea754c0f`; holdout number of that user id = `12`, of the item id used as an account id = `2`.
- **Rule values** (all in `GotThisRules`): undo window 2 hours; shop join `< 2` days from the shop's first day; window = last 7 shops; regular = ≥ 3 shops, first-to-last ≥ 14 days, ≥ ⌈2/3 × gaps⌉ gaps within `[m/2, 2m]`; lapsed when days since last shop > 2.5 × m; due at ⌈0.9 × m⌉; hint window ⌊m/2⌋ (min 1) or the category table; mute 60 days after 2 kept in a row; usual shopping day = top weekday over the last 56 days, needs ≥ 4 purchase days and ≥ 40% share; ≤ 6 chips; ≤ 3 names in a notification; "Not now" hides for 24 hours; impressions pruned after 30 days; follow-up scored after 7 days.
- **Server limits:** ≤ 500 events or rows per RPC call; name 1–500 characters; `category_id` ≤ 100; events accepted from 30 days back to 1 day ahead; 1–30 days ahead = retry; undo only when `ticked_at ≤ undone_at ≤ ticked_at + 2 hours`; `ticks` purged after 60 days, `running_low_notices` after 8 weeks.
- **No `java.time`.** minSdk is 24 and core-library desugaring is off. Day arithmetic uses `java.util.TimeZone` offsets and the `Days` helper (Task 2); ISO timestamps use the existing `isoToMillis`/`millisToIso` (`core/sync/data/mapper/SyncMappers.kt`).
- **Feature flags:** `got_this` (kill switch) and `got_this_holdout`. Both are copied to `GotThisPrefs` when flags load in the UI process, and every reader uses the prefs copy (the flag cache is empty in a background worker). Defaults before any load: not killed, holdout on.
- **Privileged SQL:** every `security definer` function has `set search_path = ''` and schema-qualified names. Helpers live in schema `got_this_private`, with `usage` and `execute` revoked from `public`, `anon`, `authenticated`. RPCs are granted to `authenticated` only.
- All user-visible copy lives in `app/src/main/res/values/strings.xml`. No item name or key ever goes into an analytics event.
- **Coverage:** Kover gates everything at 100% outside the exclusions in `app/build.gradle.kts`. Composable files (`**.ui.*Kt`), `**.di.*`, `**.data.local.model.*`, `**.data.local.dao.*` and `**.data.remote.*` are already excluded; nothing else in `feature/gotthis` may be.
- Before every commit: `./gradlew spotlessApply`. CI runs `spotlessCheck`, `lintProdDebug`, `testProdDebugUnitTest`, `koverVerifyDevDebug`.
- **Commits:** no `Co-Authored-By` or "Generated with" lines. Never `git push` without asking the user each time.
- **Production safety:** the Supabase project named `babegetthis-staging` (ref `fpzjyusgqdzqituokrwq`) is PRODUCTION. The real staging project (`vdiheceziirgvbudxdxg`) is paused. No task applies a migration or writes data to either; Task 22 hands that to the user.

## Review Focus

Inputs the spec implies but no task's tests exercised at first draft; each now has its test in the owning task.

1. **A name that normalises to nothing** ("2 kg", "x2", "!!!"). Expected: the key falls back to the trimmed, lowercased name, so the purchase is still recorded and matches itself. Test in Task 6.
2. **An item name over 500 characters** (the app has no length limit; the server rejects such events for good). Expected: the snapshot stored in the outbox and the purchase is cut to 500 characters, so the tick still reaches the partner. Test in Task 12.
3. **A list whose creator deleted their account** (`lists.created_by` is null after migration 002). Expected: the trigger credits the remaining members and does not fail on a null user. Test in Task 3.
4. **Purchases either side of midnight or a daylight-saving change.** Expected: days are local calendar days by the offset in force at each instant; 23:30 and 00:30 the next day are consecutive days and one shop. Test in Tasks 2 and 8.
5. **Very long names in the weekly notification.** Expected: each name is clipped to 40 characters like `ReminderNotifier.clip`, so three names and the count still fit. Test in Task 20.
